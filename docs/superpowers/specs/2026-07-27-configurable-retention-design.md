# 可配置保留策略设计

## 目标

把偏好设置中写死的“最多 200 条 · 保留 7 天”改为可配置项，同时保持默认行为不变。用户降低限制时，经确认后立即在后台清理超限记录及其图片文件。

## 用户界面

“保留”设置组改为两行原生下拉选择：

- 最多保留：`50`、`100`、`200`、`500`、`1000` 条
- 保留时长：`1`、`3`、`7`、`14`、`30` 天、`永久`

设置页打开时显示当前已保存的值。默认值仍为 `200` 条和 `7` 天。

调高条数、延长时长或改为“永久”时直接保存并生效。调低条数或缩短时长时，先显示确认对话框，明确说明清理不可恢复；取消后控件恢复为原值，确认后保存新值并立即清理。

## 配置模型与持久化

沿用 `AppSettings.maxItems` 和 `AppSettings.maxAgeDays`，不新增数据库字段。

- 设置页只提供预设选项；模型层接受安全范围内的正整数，以兼容已有的非预设配置。
- `maxAgeDays` 使用 `0` 表示“永久”，其他安全的正整数继续按天数解释。
- 现有正整数设置继续按原语义加载，无需迁移。
- 默认值保持 `maxItems = 200`、`maxAgeDays = 7`。

`AppModel` 提供统一的保留策略更新入口，负责校验、持久化并同步到 `ClipboardStore`。设置页不直接修改 `private(set)` 的 `settings`，避免两个控件互相覆盖状态。

## 清理流程

`ClipboardStore.prune()` 保持先按时间、再按总条数清理的顺序：

1. `maxAgeDays > 0` 时，删除严格早于截止时间的记录。
2. `maxAgeDays == 0` 时，跳过按时间清理。
3. 再按 `maxItems` 保留最新记录。
4. 删除图片记录时继续同步删除原图和缩略图。

确认降低限制后，`AppModel` 先保存并同步配置，再在后台执行一次 `prune()`；完成后回到主线程刷新历史列表。清理失败时保留已保存配置并向用户显示错误，不在主线程执行磁盘和数据库清理。

## 兼容性与边界

- 现有 `LocalClip.AppSettings.v1` JSON 已包含两个字段，因此本次不改变持久化结构。
- 已保存的非预设正整数仍可正常加载和执行；设置页显示时应能保留当前值，直到用户主动选择新预设，避免静默改写旧配置。
- `maxItems <= 0` 或 `maxAgeDays < 0` 不得进入 Store，以免越界或意外清空历史。
- 一次同时包含文本和图片的复制仍计为两条记录。
- “永久”只关闭按时间清理，条数上限仍然生效。

## 文档

中文和英文 README 都说明保留策略可在偏好设置中配置，并保留 `200 条 / 7 天` 作为默认值描述。

## 测试

使用现有 `LocalClipTestRunner` 覆盖以下行为：

- `maxAgeDays = 0` 时旧记录不会因时间被清理，但仍受条数限制。
- 调整条数和时长后，`AppModel.settings` 与 `ClipboardStore.settings` 同步。
- 降低限制后立即执行清理，并在完成后刷新历史。
- 非法值被拒绝，不会传入 Store。
- 现有按数量、按天数和图片文件删除测试继续通过。

设置页通过构建验证 SwiftUI 绑定、下拉选项和确认对话框可以编译；手工检查打开设置时显示已保存值、取消确认会恢复旧值。
